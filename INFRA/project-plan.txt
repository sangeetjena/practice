Create a complete, production-inspired local Kubernetes infrastructure lab for development, platform-engineering practice, and later deployment of an agentic workflow.
The environment must be fully reproducible, disposable at the Kubernetes-cluster level, and persistent at the database-data level.
The desired operating model is:
Git / Terraform / Helm
        |
        v
Recreate Infrastructure

Host Persistent Storage
        |
        v
Restore Existing Database Data

Kubernetes Cluster
        |
        v
Disposable
The user should be able to destroy the entire Kubernetes cluster and later recreate it without losing PostgreSQL, Cassandra, or Qdrant data.

1. Main Goal
Build a local infrastructure platform where:
Kubernetes cluster can be created and destroyed on demand.
The cluster does not need to start automatically with the computer.
Database data survives complete cluster deletion.
Recreating the cluster restores access to previously persisted data.
Infrastructure configuration is stored in Git.
Deployment is automated.
All database and application networking is declarative.
Applications use Kubernetes DNS instead of pod IPs.
Databases are not publicly exposed.
Developer access is available through controlled local endpoints.
The design should be simple enough to run on a developer laptop.
The architecture should resemble real infrastructure/platform-engineering practices where practical.

6. Persistent Storage Design
This is a critical requirement.
Kubernetes must be disposable.
Database data must not be disposable.
Use host-mounted storage so this command:
kind delete cluster --name agent-lab
does NOT delete:
data/postgres/
data/cassandra/
data/qdrant/
Use:
persistentVolumeReclaimPolicy: Retain
where appropriate.
Each database replica must have independent storage.
Correct:
postgres-0 -> /data/postgres/node-0
postgres-1 -> /data/postgres/node-1
postgres-2 -> /data/postgres/node-2
Incorrect:
postgres-0 ─┐
postgres-1 ─┼──> same directory
postgres-2 ─┘
Do the same for Cassandra and Qdrant.
Create PV/PVC configuration under:
kubernetes/storage/
Do not depend on ephemeral kind-container storage for important database data.

10. PostgreSQL / Citus Sharding

Architecture:
Application
    |
    v
Citus Coordinator
    |
    +---------+---------+
    |         |         |
    v         v         v
 Worker-0  Worker-1  Worker-2

3 workers

Example table:

    tenant_id BIGINT,
    user_id BIGINT,
    name TEXT
);

    'users',
    'tenant_id'
);

Sharding = distributing different data across nodes

36. Persistence Verification
Create:
make test-persistence
This is a critical requirement.
The test must:
Verify all databases are healthy.
Insert unique test data into PostgreSQL.
Insert unique test data into Cassandra.
Insert a vector/document into Qdrant.
Read the data back.
Record unique test identifiers.
Destroy the entire kind cluster.
Confirm host-side data/ still exists.
Recreate the kind cluster.
Redeploy infrastructure.
Wait for databases to become healthy.
Query PostgreSQL for the old test record.
Query Cassandra for the old test record.
Query Qdrant for the old vector/document.
Fail the test if any data is missing.
The output should clearly show:
PostgreSQL persistence: PASS
Cassandra persistence: PASS
Qdrant persistence: PASS
